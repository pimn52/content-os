# Content OS 技术架构

R1 是模块化单体：FastAPI + SQLite + 本地 Job/Worker + 提供商适配器 + Remotion/FFmpeg。应用服务编排产品对象，路由负责输入输出；不为实验建立第二套执行系统。

## 主链

工作区/IP → ProjectDraft、ScenePlan、EditPlan → 素材路由和生产预检 → ProductionRun → 必要的 Voice/Talking/媒体 Job → MasterNarration、TalkingRun、VideoSpec → Render → QA、复核和发布。

普通创作的创建与派发走 ProductionRun；内部评估 UI 与 Job 不注册到创作入口，评估记录保留为历史数据。

| 层 | 主要职责 |
|---|---|
| 工作区与策划 | 创作者身份、主题、文案、场景及可编辑视觉意图 |
| 媒体与路由 | 资产、Clip、来源和权利；选可用素材或说明缺口 |
| 执行与成本 | 当前能力、供应商许可、预算、幂等、Job/Worker 和调用结算 |
| Voice/Talking | 新旁白、独立 QA、人物画面与精确素材来源 |
| 时间线与渲染 | 按实际时长生成 VideoSpec，渲染、技术 QA、有限修复 |
| 复核与反馈 | 绑定确切版本的人工判断，发布后反馈进入后续策划 |

## 必要边界

- 数据库保存产品对象、来源、决策、任务和用量；媒体文件位于配置的数据根目录。持久路径不依赖当前进程目录。
- Core 只描述通用能力和结果。适配器处理厂商请求、限制、失败和费用；无法验证的能力保持未知。
- 授权在素材入库或 Profile 登记一次，Run 继承留痕。派发前检查模型许可、能力、预算、哈希和输入适配；不重复索取素材授权。中断和不明执行不得当作未调用重放。
- MasterNarration 是统一音频时轴。TalkingRun 保留片段、参考、连续性和 QA，供正常场景选择。EditPlan 保留剪辑意图；VideoSpec 是精确帧与资产的渲染契约。
- 渲染消费确切获权媒体并复查哈希、Clip、播放区间、裁切和来源限制。完成媒体与 QA、人工结论均按版本保存。
- 人工声音、人物、成片复核只对确切对象有效；失败和撤销不改写历史。

需要新增接口时先检查正常路径中的同类服务与执行契约。实现完成度与阻塞点见 [STATUS](../../STATUS.md)。
