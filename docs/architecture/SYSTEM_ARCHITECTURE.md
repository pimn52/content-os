# Content OS 技术架构

R1 是模块化单体：FastAPI + SQLite + 本地 Job/Worker + 提供商适配器 + Remotion/FFmpeg。应用服务编排产品对象，路由负责输入输出；不为实验建立第二套执行系统。

## 主链

工作区/IP → ProjectDraft、ScenePlan、EditPlan → 素材路由和生产预检 → ProductionRun → 必要的 Voice/Talking/媒体 Job → MasterNarration、TalkingRun、VideoSpec → Render → QA、复核和发布。

普通创作的创建与派发走 ProductionRun；内部评估 UI 与 Job 不注册到创作入口，评估记录保留为历史数据。

普通自动制作由 `VideoProductionService` 统一判断继续、局部修复、停止与待审。创建冲突、队列准入、完成回调、重启恢复及 UI 状态共用此入口；Worker 只领取、执行和等待，不另判下一工序。

`ProductionRun.status` 和 Job 状态描述工序事实，`next_action` 才决定生产是否继续、诊断、停止或待审；渲染完成不能覆盖未完成的复验。界面消费同一决策，不自行用旧工序状态推定成片就绪。缺陷定位与执行资格分开：纯分类共用 `presentation_diagnosis`，具体方案及派发再核对文件、依赖和预算；状态轮询不重复解码或调用模型。

`ProductionRunService` 保留事务内的依赖核对与派发，领域模块负责人物分配、素材用途及质量事实。估算与真实旁白共用人物调度器；声音投入前检查可知容量和必用替代画面，真实时长确定后复排，保留合格声音。取材始终沿原稿和同一台账，估算投影不替代人物原稿，也不重置搜索、下载或预算。

| 工序 | 输入 | 输出与交接 |
|---|---|---|
| 内容与素材规划 | 主题、创作者配置、可用素材及制作约束 | ProjectDraft、ScenePlan、初步 EditPlan、待满足画面需求 |
| 取材与用途核验 | 场景意图、素材需求 | Asset/Clip、来源、确切区间与用途 QA；下载成功不算表达匹配 |
| 克隆旁白 | 完整文案、Voice Profile、执行配置 | Master 音频、生成段、独立文案 QA 与真实时标 |
| 画面配时 | Master 真实时长、场景、合格素材与人物池 | 实测 EditPlan、人物参考分配与音频区间绑定 |
| 人物生成 | 固定 Master 区间、授权参考窗口、人物配置 | 人物段、来源绑定及独立 QA；技术通过不等于自然或同步 |
| 装配与渲染 | VideoSpec、Master、确切媒体和 QA | 成片文件、输出哈希、整片技术复检 |
| 质量反馈与返工 | 确切版本、场景/区间、缺陷及相关证据 | 责任工序、定位把握、修正范围、保留成果与复检；未知不触发全文重做 |

具体返工只传播到失效依赖；声音、人物和装配的执行资格仍归各模块，不能互借。已落地范围及缺口以 STATUS 为准。

## 必要边界

- 数据库保存产品对象、来源、决策、任务和用量；媒体文件位于配置的数据根目录。持久路径不依赖当前进程目录。
- Core 只描述通用能力和结果。适配器处理厂商请求、限制、失败和费用；无法验证的能力保持未知。
- 授权在素材入库或 Profile 登记一次，Run 继承留痕。派发前检查模型许可、能力、预算、哈希和输入适配；不重复索取素材授权。中断和不明执行不得当作未调用重放。
- MasterNarration 是统一音频时轴。TalkingRun 保留片段、参考、连续性和 QA，供正常场景选择。EditPlan 保留剪辑意图；VideoSpec 是精确帧与资产的渲染契约。
- 渲染消费确切获权媒体并复查哈希、Clip、播放区间、裁切和来源限制。完成媒体与 QA、人工结论均按版本保存。
- 人工声音、人物、成片复核只对确切对象有效；失败和撤销不改写历史。

需要新增接口时先检查正常路径中的同类服务与执行契约。实现完成度与阻塞点见 [STATUS](../../STATUS.md)。
