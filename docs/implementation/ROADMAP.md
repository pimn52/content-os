## 当前技术路线：复用成熟能力，停止重复造轮子

1. **媒体与视觉（优先复用）：**继续 Remotion + FFmpeg；先实现可靠的完整源画面/设计式 9:16 容器、字幕区域处理及按内容需求可选的既有语义图文，不预设固定模板数量或通用最优风格。若需要人脸区域判断，先评价成熟 FaceDetector（例如 OpenCV YuNet 或 MediaPipe）能否以少量代码实现可靠的保守 preflight；检测失败退回 contain 或要求换素材，不靠猜测 crop。
2. **剪辑/镜头理解：**仅在真实剪辑需求无法用现有素材时间线满足时，考虑 PySceneDetect（已有开源镜头切分），不重写通用 CV 引擎；跳剪/停顿可参考 auto-editor，但其自动静音剪辑不能替代内容导演。任何新依赖先核许可/体积/实际兼容性。
3. **音频/本地运行时：**优先隔离的官方支持 Python 环境、发行版预编译 wheel（如 SoundFile 官方 Windows wheel）、现有 FFmpeg 或标准库 WAV/PCM 路线。通过受控子进程、精确依赖版本、基础文件 hash/来源、现有 ledger/consent/admission 管理，不继续自研 PE import scanner、SxS activation graph、CFFI 扩展/发行商列表抓取协议。若安全/授权基线无法被现成路径满足，记录明确阻塞，不以退化安全为代价。
4. **Provider：**保留已审核配置的 OmniVoice + LatentSync 内部评估路径；不横向模型竞赛，不擅自将官方非商用权重视为商业可用。
## 反膨胀执行纪律

- **前置必须过才进入下一里程碑。**一个里程碑可再拆最多两项实施任务；如仍需拆分，先由产品审查确定是否缩小目标或更换成熟组件，**不能递归细分原生证明/协议实验**。
- 每包先确认是否能使用当前代码、现成安装包/开源工具，评估改造工作量；只有无法复用时才新增基础设施。
- 每包最多两种实质不同的修复方式；到限时标记 FAIL/BLOCKED，附最小复现/可替换方案。不凭“通过更多 fixture 测试”代替真实成片/正常 UI。
- 在前置缺失时允许输出清楚的 `BLOCKED` 与人工所需动作，不允许为了让状态持续 RUNNING 而再开一个 C4 子包。
- 不允许扩大 `main.py`、自研 Windows native binding/security 证明、再加层 Run/Plan 概念、提升通用 QA 门槛，除非**一个真实 R1 阻塞**和不超过一页的替代方案对比充分证明必要。
- **用户人工时间与最终可发布质量优先于自动化理论完整性。**证据要分别报告：合同/fixture、真实媒体、普通 UI、人工质量、复用性与成本。
- 一包关闭后，当前产品事实回写模块规范；历史修复细节留 Git/本地 evidence；STATUS 不当日记。禁止在用户没有新授权的情况下自动启动下一里程碑。
