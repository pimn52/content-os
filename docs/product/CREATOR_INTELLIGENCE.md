# 创作者、IP 与选题

本页是创作者身份、受众、知识、选题来源、文案偏好和反馈事实的唯一权威来源。主题如何变成 ScenePlan、镜头如何选材以及 Voice/Talking 如何执行，分别由[场景规划](SCENE_PLANNING.md)和[能力权威索引](CAPABILITY_INDEX.md)中的模块负责。

## 长期资产

- 工作区保存 IP、受众、知识、表达偏好、授权关系、历史作品和反馈；项目与视频都是该工作的产物。
- Creator Brief 由创作者一次建档：IP 定位、专业领域、平台分区/赛道、内容支柱、常讲主题、目标受众、可用于规划的知识与观点、常用词汇/钩子、表达风格、适用边界和避免表达。`knowledge`/`opinions` 视为允许进入规划的表达性资料，不存放密钥、联系方式或私密事实。
- 赛道和内容支柱优先从已授权本人长素材、创作者明确说明和公开账号历史证据建立；产品测试主题、临时实验项目和模型猜测不得进入创作者画像。每个 Profile 保存对应素材/账号证据引用，切换项目不能把另一个创作者的主题套进来。
- 公开账号可由创作者提供主页链接并关联只读账号。只有实际导入/分析过的历史标题、说明、指标或摘要进入规划；链接本身不等于已分析粉丝画像、平台分区或近期内容。多平台历史最多取 8 条，并按账号轮转，避免第一个账号独占规划上下文。
- 身份、经验、立场和专长必须来自已登记事实。模型可以组织表达，不能替创作者虚构亲历、数据、客户或结果。
- 每次规划只发送与本次主题词相关的有界条目，并对 URL、邮箱和长号码脱敏；身份凭据、同意材料和任意 metadata 不进入模型。资料状态分为 `structured`、`topical_only`、`empty`，资料稀疏时明确降级，不增加每次开跑的建档硬门。
- 主题可由用户输入或已登记机会提出。引用资料、发布时间、来源和适用范围随选题保存；过期或无法确认的事实保持未知。
- 自动化在既定内容范围、节奏和预算内自主选题与推进。关键依据不足时可暂缓该主题并换题，不能为了出片制造证据。

## 文案与反馈

- 文案保留创作者立场和受众关系，区分事实、判断、建议和修辞。用户改稿是新的编辑事实，不能被模型或恢复流程覆盖。
- 选题、标题、文案和表达建议可以修改；建议须说明依据与适用范围，不把一次样片偏好升级为通用规则。
- 负反馈绑定确切作品、版本、场景或表达方式，只约束相应范围；不封禁无关原素材，也不改写旧审核事实。
- 新规划读取同一创作者已登记的作品占用、导入的公开账号历史和反馈观察；模型反馈用作上下文，不代替本次创作判断。
- 文案完成后再进入 Voice 和 Talking。模型时长、人物容量或素材短缺不能反向删减主体、主张和必要证据；真实执行约束由调度返回给编辑决策。
- 同一 Creator Brief 可用于不同主题，但每场规划须说明内容支柱、主题适配理由、受众价值、采用的知识/观点、事实缺口和偏离风险。只有引用本次 Brief 中的原文才可记为有依据；结构化 Profile 下没有任何内容支柱/知识/观点依据的场次视为赛道未验证，不能保存为正常计划。
- 不同创作者必须使用独立 Profile；毕英杰与 TIM 的赛道、主题、受众和素材证据不能共用一组测试 Prompt 自动混合。用户修改 Profile 后旧场景计划按版本失效，重新规划时使用新版本。
- 平台要求登录或页面无法公开验证时，保留“未确认”状态，不根据同名账号、搜索摘要或单条提及猜出官方主页。
