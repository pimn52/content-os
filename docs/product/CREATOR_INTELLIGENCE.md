# 创作者、IP 与选题

工作区保存创作者身份、受众、知识、表达偏好、素材授权和历史反馈。新主题从这些事实生成可编辑文案与 ScenePlan；用户可修改，模型输出必须按同一结构校验后再保存。

## 产品行为

- 主题可由用户输入或有来源的机会记录提出；引用的资料与发布时间可追溯。
- 文案、克隆旁白、本人 Talking 和说明画面共同规划，默认无需重录口播；可替代画面优先采用现有可行方案，补拍限不可替代的现场、操作或结果证据。
- 自动规划先读取与装配共用的字幕处理及输出布局，已知不可用区间不反复核验。用途核验后仍有缺口，可在原任务内用已有合格候选调整一次画面；保留原旁白、主张、证据要求和图解，再走同一核验。无实际调整不重核，失败不重发请求，预算不足保留后段额度；用户改稿立即停止覆盖。
- 项目可保存“自动规划”或“本人讲解 + 说明画面”。后者保留本人说新文案，其他画面按内容需要选择，不强制动作实拍或固定字卡比例；更改方式保留文案并重新规划。结构满足不代表成片质量通过。
- 素材、账户数据与发布结果按工作区隔离；反馈只影响新方案，不能改变旧作品的审核事实。
- 编辑建议须标明依据和适用范围；用户可不采用。不能把一次样片的偏好变成通用规则。
- 解释步骤、信息损失或多因素关系可选对应信息图解，规划、普通编辑器与渲染使用同一契约。静态字卡只用于有理由的标题或结论。
- 自动因素图仅在旁白明确枚举且标签可逐字对应时删除多余项，不改文案；有歧义的数量矛盾保留具体缺口。原规划返回保留，缓存与同稿恢复沿用同一规则。
- 新规划读取同一创作者的已登记画面占用与具体成片观察；普通界面从服务端恢复反馈，完整成片接受/拒绝绑定确切 Render，不能将渲染成功显示成质量通过。

## 当前能力与缺口

工作区、IP/项目/草稿、机会与只读历史记录、发布及反馈记录已有基础。负反馈、前置呈现检查及一次自动画面调整有夹具；真实模型的调整有效率、跨主题成片质量和一次输入完整编排尚未通过。
