# 生产资源调度

本页是跨场景、素材、Voice、Talking、预算与渲染工序的资源顺序和有界优化策略的唯一权威来源。场景规划、媒体来源、Voice、Talking、执行准入和渲染仍由各自权威文档定义。

生产资源调度不是第四种内容能力。它回答“在不改原文、不过预算、不伪造素材事实的前提下，当前作品能按什么顺序、用哪些合格资源完成”。

## 调度目标

采用分层约束下的确定性近似最优，不宣称数学全局最优：

1. 先排除不合法或不可执行：授权、来源哈希、画幅、时长、字幕、人物身份、模型能力和预算。
2. 在可执行候选中优先满足表达任务，再比较整片无意重复、同源信息变化、横屏次选、历史占用、本人素材价值和成本。
3. 先完成画面可行性，再投入高成本 Voice/Talking；真实音频时长出来后重排画面，不重做已合格 Voice。
4. 任何批次失败不留下部分派发；可复用事实、完成文件和预算记录优先复用。

硬边界只保留同意、授权、预算、媒体/模型事实、幂等和当前技术 QA。可选优化、内容重复、素材不足或质量风险通过停点、备选和人工最终判断处理，不叠加新的形式门禁。

## 主链调度

| 阶段 | 调度动作 | 失败处理 |
|---|---|---|
| Planning | 读取创作者、真实素材事实、画幅、人物池、预算和实际 planner 配置；生成完整 ScenePlan，必要时做一次有界视觉修订 | 保留脱敏响应与用量；不无限重试、不改写原稿绕过 |
| 素材可行性 | 按表达作用和 candidate evidence 解析本地、外部和已声明备选；候选不足时按原稿允许范围补缺 | 未知或不合格素材不能被检索分数、下载成功或图解冒充通过 |
| Voice | 核对 Profile、参考窗口、runtime 参数和预算后生成唯一 Master；Voice QA 独立核验 | 单段已知失败可局部修复；未知、多段或状态不明失败不盲目重生 |
| 实测画面重排 | 用主音频真实语句时轴重新安排 A/B-roll；人物池按整批回溯分配连续窗口 | 原片不足时沿既有分句和原稿备选重排；不裁剪原文 |
| Talking | 所有人物窗口先统一分配和校验，再按最终段数派发；每段 QA 后进入装配 | 不产生部分批次；已派发窗口固定，状态不明不重发 |
| Render | 消费确切 Voice、Talking、素材和 VideoSpec，重核哈希与来源后渲染 | 失败保留旧文件与账目；纯装配问题不重跑模型 |

## 有界算法

媒体候选先按表达作用与匹配度筛池，再做整片联合选择。每个场景最多比较 8 个候选，每步保留 64 个组合；排序依次考虑无意重复、横屏过度使用、信息变化时仍用同源、来源作用、本人素材价值、质量与匹配度。组合展开只复用已解析来源，不重复扫描数据库或调用模型。

已完成的连续视频区间核验可以被新镜头意图复用。若规划器明确选中该 Clip，来源哈希、字幕净空、连续性和画面描述都有效，且镜头主体/动作与描述有至少两个非泛化词义相交，调度可记录独立的 `local_description_matches` 并直接选材，不再把同一段视频重复送视觉 Provider 做用途问答。该复用不覆盖来源中的否定描述；弱匹配、描述冲突、素材未核验或没有明确 Clip 选择时仍走正常用途核验。

Talking 池按同一来源连续前向窗口分配，整批按短窗口优先探索，最多访问 50,000 个状态；失败不接受局部最优或部分结果。估算和真实 Master 共用同一调度器，真实时长只改变输入时长。

外部供给顺序为：已授权本地资产 → 素材 API/公共目录 → 网页 Search/Fetch 与公开原文件 → AI 生成。该顺序是默认供给策略，不替代具体表达任务；调用次数、时间、文件大小和预算限制以[媒体资产与选择](MEDIA_ASSET_SYSTEM.md)为准。

视觉成本按实际产物而非“有没有 AI 参与”计算：

- 本地 `typography`/diagram 由 Remotion 确定性渲染，没有图像或视频生成 provider 调用；AI 规划图解要点不等于 AI 生成 B-roll。只有场景确实需要文字关系表达时才优先使用，不能用字卡掩盖缺素材。
- 外部 stock 的成本包含检索、下载、入库和用途核验；有真实画面需求时用于替代抽象图解。
- AI 图片/视频是独立高成本补位，必须有具体表达收益、估算成本和剩余预算才可派发。调用失败或效果未知不能重试到预算耗尽，也不能把 AI 规划调用记成零成本媒体生成。
- 当前 `f22e0bac...` 的 4 个 B-roll 均为 `local-typography`，AI 图片/视频 B-roll 为 0，外部 stock 为 0；审计见 [broll-source-cost-audit.json](../../content-os-data/evaluation-evidence/ordinary-ui-autonomous-v6-20261107/broll-source-cost-audit.json)。

人物容量不足时，只有原稿已明确给出 `supporting_visual_intent` 的本人段可投影为说明画面。投影后若 fallback 只有本地/历史资产且无法满足用途，自动加入 `stock` 作为低成本候选；原有本地候选先比较，外部视频仍须经过同一区间用途 QA，stock 命中不等于画面通过。

已有一句本人场景被真实 Master 拆成多个 `--speech-` 子段后，若全部 A-roll 超出连续人物窗口，保留优先级最高且容量内的子段作为可见 A-roll，其余子段保留原旁白并转为本地要点卡。该降级只适用于实测 speech part，普通未拆分且明确要求本人出镜的场景仍不能静默改成字卡。

## 原子交接

- ProductionRun 是普通生产决策入口。创建、继续、局部修复、停止和待审共用同一状态与 `next_action`；UI 和 Worker 不另判下一工序。
- 调用前在事务中检查当前快照、预算、幂等键和依赖，完成或失败后持久结算。预算保存与待派发任务绑定，避免保存成功但任务丢失。
- Voice、Talking 和 Render 使用有界租约与资源键；重领不重复发送状态不明的付费请求。
- 已合格 Voice 和无关 Talking 段在局部修复时复用。依赖变化只失效实际消费者，不整片无条件重生。
- 已完成 QA、当前 Run 的技术合格结果可自动进入下一步；最终整片质量仍由用户判断。

## 当前边界

有界算法降低搜索成本并保留可解释排序，但重复最小化和高图解占比仍是软结果，不是硬保证。未知费用、来源坐标、模型能力或人物对齐保持未知，不能写成零成本或已通过。

最近一次三能力真实 Run、各工序产物、调用账目和已知缺口只看 [STATUS](../../STATUS.md)。夹具证明路由与失败处理，不证明跨主题审美、Voice 自然度、口型 likeness 或发布质量。
