# 发布包装与学习闭环

本页是发布包装、人工发布回执、平台指标、成片反馈和下一轮建议的唯一权威来源。ScenePlan 如何消费创作者规则由[场景规划](SCENE_PLANNING.md)定义；渲染版本事实由[时间线与渲染](TIMELINE_RENDER_LEARNING.md)提供。

## 可发布输出

发布和成片反馈只能绑定当前项目内已完成、文件可用的 `render:<render_id>`。草稿版本、失败 Render、未知 Render 或其它项目版本不能冒充发布输出。普通 UI 从实际输出目录展示分辨率、时长、文件可用性、发布状态与反馈状态。

## 发布包装与回执

一次人工发布记录同时保存：

- 确切输出版本、平台和可归属当前 IP 的平台账号；
- 标题、描述、视频封面取帧及发布时间；
- 内容 URL、平台内容 ID、指标、指标来源和观察窗口。

封面取帧必须位于成片时长内。渲染完成不代表已经发布；只有人工发布回执或后续真实发布任务能产生发布记录。当前自动发布仍是 `not_developed`，普通 UI 不伪造平台回执。

## 反馈与学习

- 成片反馈绑定确切 `render:<render_id>`，按作品、版本、修改字段和拒绝原因生效；草稿问题继续走制作观察与局部修复，不混入发布反馈。
- 指标按发布记录、观测时间、发布后窗口和来源追加为不可覆盖快照；同一窗口的旧快照保留，不用最新值覆盖历史。
- 自身基线只比较同一创作者、同一平台、同一观察窗口的历史作品。0 个对照为 `insufficient`，1 个为 `emerging`，至少 2 个为 `ready`；基线使用共同数值指标的中位数。
- 下一轮建议读取最近 4 条成片反馈、最近发布回执和最新指标快照基线。单条播放数据不能直接归因于钩子、声音或画面；无指标或对照不足时只保留“不能归因”的事实。
- 只有创作者明确采纳的跨作品规则才能进入后续规划。原始反馈、指标和单作品建议不等同于长期偏好。

## 历史发布与本素材

历史发布记录可以绑定同一 IP 的本地 Asset，用于让规划同时理解“当时公开讲了什么”和“本地长素材对应哪条节目”。官方原帖、已下架官方原帖和公开补档分别记录状态；补档 URL 可以证明内容对应，但不能把补档播放量写成官方指标。原始发布时间只有日期级证据时不得伪装成精确时刻。

## 当前能力与缺口

已有完成 Render 输出目录、发布包装与人工回执、版本绑定、成片反馈、不可覆盖指标快照、自身平台窗口基线和带证据的下一轮建议夹具。尚缺平台自动回执、自动发布、自动指标同步、评论信号、实验管理和真实跨作品学习效果验证；这些不能写成已完成。
