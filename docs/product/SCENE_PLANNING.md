# 场景规划

本页是场景规划行为的唯一权威来源。创作者身份、媒体选取、Voice、Talking、调度和渲染分别由[关联模块](CAPABILITY_INDEX.md)负责；这里只定义主题如何变成可执行 ScenePlan。

## 产品目标

从完整主题或稿件出发，同时安排文案、镜头意图、本人出镜、图解和待满足素材需求。规划必须先保证内容完整，再判断现有资源能否执行；不能为了迁就短素材、缺失画面或人物容量删减主体、改窄主张或自动改推大字卡。

输出是可编辑、持久化的有序 `ScenePlan`。每条计划包含确切口播、目标时长、视觉意图、首选/备用来源、画面要求和观众应带走的信息；用户修改后按同一契约重新校验。

## 规划契约

- 开场先完整交代主体和问题。`creator_led` 项目至少要有一场可见的本人讲述；普通项目可按内容选择本人、实拍、外部素材或图解，但 IP 辨识度不能从计划中静默消失。
- 普通短视频默认采用真实画面主导：没有创作者明确要求全本地文字/图解时，本人素材或其它实拍应覆盖约 40% 以上时长，且不能连续三场只有文字/图解。历史、科技、自然、现实生活等具象主题应主动查找应景 `stock`；查询只是取材意图，取得后仍须校验实际用途。
- 当前 IP 有匹配声音、可见人物参考和可用人物池时，普通自动规划必须保留至少一场本人可见讲述；素材容量、横屏适配或检索不足都不能让本人辨识度静默消失。创作者显式要求不出镜，或当前没有可执行人物能力时，才按可用画面规划。
- 规划上下文可从当前 Creator Brief 的内容支柱与常讲主题推导有界视觉母题，例如哲学/历史内容会补充古籍、图书馆、遗址、石柱、书写和沉思等检索词。这样能把已入库的真实 stock 提给规划器复用；母题命中只是候选提示，仍需逐场判断适配，且“无书写动作”“没有人物”等否定描述不能反向形成命中。
- `voice_text` 是后续 Voice 的输入，不能因 Voice/Talking 模型时长限制被截断。目标时长是估算，真实配音后由调度和 EditPlan 重新解算。
- `visual_requirement` 明确 `creator_speaking`、`action_evidence`、`explanatory` 或 `unknown`。非 `unknown` 时须有编辑理由；操作、界面和结果等不可替代证据不能被 AI 画面冒充。
- `creator_speaking` 可以由本人参考加 Voice/Talking 完成，也可以声明可替代的 `supporting_visual_intent`；替代只作用于原稿允许的画面，不改完整旁白，也不把必需事实表演降级。
- `material_request` 只表示尚未取得的 `stock` 或 `ai_broll` 画面。已有 Clip、`creator_speaking` 和不可替代事实证据不能同时填写新取素材请求；自动产品默认不请求新 AI 视频。
- `preferred_clip_id` 只是可选的已有素材提示。模型给出未提供、未知或短于场景时长的 Clip 时，清空该提示并保留视觉意图，由正常素材调度重新选择；已知被权利或呈现条件阻断的素材仍不得使用。
- `preferred_sources` 与 `fallback_sources` 是可执行来源意图，候选仍须经过素材用途核验。新素材需求保存查询、理由和来源类型，不能假称文件已经取得。
- 图解只表达真实关系、过程、数量或信息损失；可执行图解须有明确 treatment 和短标签。静态大字卡只用于标题或结论，不用于掩盖素材缺口。
- 一次有界视觉修订只能更换画面。若某场原本是 `explanatory`、没有既有图解，且当前已核验素材都不匹配，可新增一个真实 `diagram` 并把主来源改为 `typography`；只允许表达关系、步骤或信息损失，不能写文字卡、不能复述旁白，也不能用于 `creator_speaking`、`action_evidence` 或不可替代事实证据。已有图解不得在视觉修订中替换。
- 当创作者显式要求“全片只用本地产图解和文字要点”时，模型返回 `unsupported` 表示该场没有可声明的关系图，不等于没有可执行画面。产品按场次作用生成受支持的本地文字卡：开场问题用 `headline`，对比用 `contrast`，其他要点用 `key_point`；标签只来自已规划的短语义强调、观众收获和场景目的，不复制整段旁白。该文字卡例外只适用于显式本地约束，不能成为普通自动制作绕过缺素材的后门。
- 规划读取已授权素材、真实区间线索、输出画幅和人物池摘要，但不把采样描述、旧短片认可或配置存在当成执行通过。
- 每场新计划包含 `creator_fit`：匹配等级、内容支柱、主题适配理由、受众价值、采用的知识/观点、事实缺口和偏离风险。支柱与知识/观点引用必须逐字来自本次筛选后的 Creator Brief；无法对应时移除，并把原因写入缺口或偏离风险，不能编造 IP 立场。
- 结构化 Creator Brief 下，每场至少要有内容支柱或知识/观点依据；全部场次都无依据时拒绝保存为正常计划，并提示“当前主题未通过创作者赛道验证”。稀疏 Profile 保持泛化建议，不新增建档门禁。

## 自动运行

`generate_scene_plan` 先读取创作者、项目、素材和运行事实，再调用当前 `RuntimeSettings` 中配置的 scene planner。provider/model、输出模式、推理档位、输出上限和超时属于运行配置，不是场景规划的内容规则；每次调用沿用预算、幂等和用量记录。

返回必须通过完整 JSON/schema、场景顺序、开场主体、人物与来源、图解、素材依赖和 Creator Fit 引用校验后才保存。Creator Fit 缺失或资料稀疏不会阻断出片，但会明确降级为部分匹配/泛化建议；伪造的内容支柱或知识/观点引用会被剔除并留下证据缺口。可执行画面不足时允许一次有界视觉修订，只调整画面意图和来源，不改写原文、主张、证据要求、Creator Fit 或场景顺序；未知/无效响应保留脱敏诊断，不无限重试。

模型返回的整数形式时长、Creator Fit 同义字段和无害附加元数据在进入契约前归一化；无法使用的场景时长按口播文字生成有界估算，后续仍由真实 Voice 时长重解算，不把估算写成实测。若 Provider 仅在未转义的 ASCII JSON 键后误写中文/ASCII 分隔符，或该键缺少闭合引号，产品按语法确定性恢复为标准 `key:`；正文、中文内容和所有业务字段随后仍须通过完整 schema 校验，不能借修复放宽场景规则。

Provider 若把 `topic_fit_reason`、`audience_value` 等已登记的 Creator Fit 字段误放进 `visual_intent` 或 `supporting_visual_intent`，产品只移除这些已知错位注解，场景自身的 Creator Fit 保留并照常校验。其它有值的未知字段仍拒绝。

`supporting_visual_intent` 只适用于可替代的 `creator_speaking` 场景。Provider 若把它误放到已有主画面和备用来源的 `explanatory` 场景，产品清空这一非承载注解，不新增画面要求或把本人切出当必需条件。

`diagram_loss` 只表达源与损失端点，必须恰好两个标签。Provider 若给出三个以上节点，产品把同一组节点按原有顺序归一为 `diagram_flow`，保留全部语义；不删节点、不改旁白，也不把流程卡用于事实证据。

关联到当前 IP 的只读公开账号可提供历史标题、说明、指标和有界摘要；每次最多 8 条并按平台轮转，链接本身不视为已分析。没有实际历史证据时不推断分区、受众或近期内容。登录墙后的同名搜索结果不进入规划证据。

素材上下文总量保持有界。已经完成连续区间核验的 stock 若与场景镜头意图明确相交，规划器可优先选择确切 Clip；未核验、弱匹配或主题无关的候选不能因为出现“书”“人物”“遗址”等单个词就自动进入成片。

规划估算和真实 Master 都使用同一人物容量调度。真实时长导致画面不足时，沿原稿允许的标点和备选重新配时或换材；只有原稿已有可执行图解时才可直接回落，不能临时发明无关补位。
