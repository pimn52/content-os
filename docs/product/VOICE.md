# Voice 克隆旁白

本页是 Voice 生成、停顿配方、独立 QA 和语音修复的唯一权威来源。Voice 输出 `MasterNarration`，与已批准文案、授权声线、确切参考窗口、实际音频和时间轴绑定；Talking 与跨工序调度不在本页另定规则。

## 当前方案

普通生成从 Voice Profile 的版本化 `generation_recipe` 读取质量锚、参考窗口、runtime、参数哈希、composition policy、停顿配方和交付调整。当前工作区使用 V60 人审质量锚、W13 本地 OmniVoice runtime、`28.24–34.24s` 授权参考窗口、`paragraph_spans` 合成和 recipe v6；具体对象 ID、哈希和最近一次真实产物以 [STATUS](../../STATUS.md) 为准。

配方或 runtime 参数变化必须进入新版本并重新核验。历史 W51 或旧音频的人审结论不继承到新配置、新参考窗口或新音频。

## 重音与语义焦点

- 重音是与停顿、读音并列的独立表现层。产品先判断“哪个语义单元要成为焦点”，再决定如何执行；停顿更长、全局 speed 变化或整段音量变化都不能代替重音。
- `voice_emphasis.py` 的当前规则集为 `zh-focus-emphasis-v1`，覆盖序列收束“最后/最终”、数量框架“记住三步：”、短断言和对照修正肯定项。普通自动 Voice 在 Draft 没有人工 performance plan 时会生成 emphasis-only assisted plan；有 Draft plan 时保留其确切版本。
- 规则显式排除普通时间“最后一天”、非序列“最后，终于”、非框架数量“三步并作一步”和普通“一点”。未知结构不强行重读；最多保留 8 个焦点，避免整段机械加重。
- Provider 文本只在精确焦点单元前后建立生成边界，可见原文、字幕和 QA 目标不变。输出段必须与 cue 字符区间完全对应，否则记录跳过，不能把近似命中写成已应用。
- 当前本地执行只提升对应 PCM16 段的能量：`strong=+1.58 dB`、`clear=+0.98 dB`、`light=+0.51 dB`，段首尾使用 10 ms 渐变，不改时长、不改全局 speed、不插入静音。焦点后的实测接缝不参与段落静音压缩。
- 修改过的焦点分段另存为新的 `.focus-emphasis.wav` part，并更新 part 哈希和来源路径；Voice QA 从这些实际 part 与静音 cuts 重建 Master，必须与最终音频逐字节一致。
- metadata 保存 plan、命中的原文、规则、Provider 前后边界、实际增益、RMS 前后、part 哈希、跳过原因和最终音频哈希。技术 QA 只能证明绑定与执行，自然度和重音是否像真实讲话仍由用户对确切音频判断。

## 生成与 QA

- 文案意图与提供商时长限制分开。本地克隆按完整场景分段，模型只加载一次；保存每段文案区间、音频、采样区间及哈希，再合成 Master。
- 模型输出片段和最终 Master 均保留来源。Voice QA 先核对 PCM 分段与 Master，再逐段独立 ASR 并汇总全文；不向识别器提供目标文案。
- 真实缺词、重复、明显多出内容或不可播放仍失败。中文同位置替换只有上下文默认读音与声调一致时才记为同音差异；声调、声母、韵母或词义不确定的替换均进入 `copy_substitution_tokens`，不会因为整稿较长、替换比例低就自动放行。例如“痛苦”被识别成“痛哭”必须返工，不能作为 B-roll 或字幕文本继续。
- 数字书写差异只在明确的计数/时间单位前归一：例如“两千年前”与“2000年前”、“三步”与“3步”。归一记录为 `spoken_quantity_units_v1`，只存在于比较流；原始文案、ASR 文本、字幕和时间轴均不改写。“万一”“一直”等普通词语不按数字改写。
- ASR 分段偶发的小范围时间戳重叠不改写文本和 QA 结论：≤250 ms 的相邻重叠把后段起点归一到前段终点，并保存 `transcript_timing_normalization` 证据；超过 250 ms、空段或非正区间明确失败。
- 本次自动执行且技术 QA 合格的旁白可进入本 Run 的待审成片，不等于人工认可或可跨执行复用。U-Voice 的 likeness、naturalness、emphasis、pace、pauses、rhythm 只对确切音频有效。
- 字幕使用本次生成原文，时间只取独立 ASR 与原文词边界相交的结果。识别同音错字保留在 QA 证据，不直接改写新字幕。
- Voice QA 保存独立 ASR 的实际 provider/model/runtime/machine 与参数快照。修复只核对这个已观察身份、当前脚本和来源哈希；商业档、许可标签或“质量已验证”标签不能成为普通修复的额外门禁。
- 单段失败可由普通队列只重做该段，复用其余合格片段并在重组后重新全文核验。逐段转写与整片 ASR 可以采用不同的分段接缝；修复要求有序 spoken token 一致，不要求 ASR 分段对象逐一对齐。未知、多段失败或来源变化仍不盲目重生。
- 当独立 ASR 定位到目标汉字被替换时，修复器用有序 token 对齐该失败段，只对目标位置生成 Provider 私有拼音控制；例如“痛苦”被识别成“痛哭”时对目标“苦”应用 `KU3`。控制只改 Provider 输入，不改可见原文、字幕和整句，也不把“痛哭/痛苦”写成单句特例。
- 多个生成段各自出现可定位的缺字或读音替换时，产品在一次有界返工内批量生成目标字符控制，再重做一次完整 Provider 输入并重新全文 QA；不再把一个专名重复出现在多段误判成多个未知阻塞。失败段可以同时带 `copy_phonetic_equivalence` 记录，但重复、长静音、不可播放或任何无法逐字定位的故障仍停止诊断。每个失败的缺字/未解析替换都必须有一个与目标字符完全对应的修复，数量必须一致；已经同音的视觉异形字不产生无关拼音控制。
- 当需要纠音的字符位于全稿重复出现、至少三字的 CJK 术语中时，按术语位置输出完整拼音序列（例如按上下文得到 `SI1 DUO1 GE2`），而不是只替换术语中一个字；这是音节边界修复，不写死整句，也不改变可见文案、字幕或 QA 目标。
- 如果目标字已经被同音词条替换，后续字级返工不得再次对它施加拼音控制；系统按“原稿字符数 − Provider 字符数”确认该差异来自既有别名后才跳过，其它无法定位的字符仍失败。

## 停顿配方

| 层级 | 规则 |
|---|---|
| 词组内部 | 连续，不切断词组 |
| 逗号/继续从句 | 短边界，轻带过 |
| 句号/问号 | 自然收束，停顿必须高于逗号 |
| 段落 | 可留一拍 |
| 关键观点 | 可留一拍思考空间 |
| 片尾 | 自然落下 |

- 全局 speed 不是停顿控制器。历史 V36 全局加速因听感变平被人审否决，不能用参数变化冒充层级处理。
- V60 运行只处理已知段落接缝的 `terminal/continuing` 边界；`no_break` 与 `forward_binding` 保持原音。逗号、句末和关键观点处不自动插入统一毫秒值。
- 只删除实测静音：10 ms、-45 dBFS 窗口，每侧至少保留 60 ms，单次最多删除 300 ms；不改语音帧、不插入未实测静音、不改全局 speed。
- 没有实测静音、静音长度不足或压缩超过上限时原样保留并记录原因，不为执行配方形成新阻断。
- 生成 metadata 保存 raw/final 哈希、每个接缝的文案位置与边界类型、实际 cuts、跳过原因和最终分段时轴。Voice QA 从原始分段和 cuts 重建最终 Master，字节一致才通过。
- 调整通过 Voice Profile 的 `generation-recipe` 接口进行。V19C 的 180 ms 单点补静音是历史样本证据，不是默认参数；V60 证据为 `content-os-data/evaluation-evidence/v60-length-completion/manifest.json`，句末高于逗号证据为 `v19b-u-voice-punctuation-hierarchy-review` 及对应 V19C JSON。

### 交付文本与异读控制

- 可见文案是 QA、字幕和下游的唯一原文。Provider 可另行接收版本化交付文本，只修改标点、短语生成边界和已审核读音；非标点文字不得被普通文本替换悄悄改写。
- `punctuation_overrides` 可把特定语义边界的逗号改成句末或分号，以让模型形成正确短语；原文仍保留用户批准版本。
- `contrastive_correction_break` 识别“不是 A，是 B / 而是 B”的对照修正结构：A 是完整否定项，逗号改为句末并把 B 独立生成。规则不绑定“跟风”“城市”等具体词，且“不是 A，也不是 B”“这是不是 A，是 B”等非对照结构不触发。
- `predicate_completion_break` 识别动词与结果补语已经完成谓语的边界，例如“A 和 B 分开，后项……”或“方案做好，后项……”。停顿放在完整谓语之后，不拆开动词和补语。当前规则集覆盖常见“动词 + 开/完/成/好/到/掉/清楚/明白/干净”组合；后接“再/又/才/然后/先”等继续关系时不改边界。
- `generation_breaks` 和具体 `punctuation_overrides` 仍作为已审例外兜底，但常规对照与结果补语问题由 `voice_syntax.py` 的规则集处理，不写入整句词条；模型段位置会映射回原文段落，Voice QA 不按 Provider 文本长度冒充原文。
- 反向映射按段落实例校验，但目标 break 若已经等于某个原稿段落的 start/end，不重复切分；它只是对既有段落边界的强化。文本外、重叠或无法归属的 break 仍失败。这样“系词短补语句末恰好也是段落端点”不会让真实生成音频被误判为输出无效。
- `copula_complement_break` 是通用句法规则：当文案呈现“主语，是短名词补语。”时，Provider 文本去掉主语后的逗号，把“是+补语”绑定为一个完整谓语，并在补语后的句末建立独立生成段。例如“最主要的原因，是照明。现在……”会生成为“最主要的原因是照明。”和“现在……”。规则不依赖“原因”“照明”等具体词，最多 12 个字的短补语都适用；与已审核显式调整重叠时，显式调整优先。测试至少覆盖两个不同“主语+短补语”组合、与显式短语调整的重叠优先级，以及最终 Master 到原文段落的反向映射。
- `contextual_pronunciation` 根据局部语境判定多音字。当前 `差` 规则在“质量/条件/效果类主语 + 差作谓语”时选择四声 `chà`，输出 Provider 文本 `CHA4`；支持“照明差”“信号很差”“画质比较差”等不同主语和程度词，不依赖某一整句。`时差/温差/差异/差别/出差/参差/差不多`等差异、差遣和非均衡词不被该规则覆盖。
- `pronunciation_overrides` 仍保留给无法由语境可靠判断的专名或客户明确指定读音；它不是“照明差”这类常规语境问题的默认修法。Provider 对数字拼音控制不稳定时，可保存逐字同音、同声调的 Provider 私有别名（例如“斯多葛”实际送入“斯多格”），但必须通过逐字读音校验；可见文案、字幕和 QA 目标仍保留原文。
- 交付调整必须有理由和证据引用，并记录 `pending_user_review` 或 `approved`。前三处短语、系词短补语和“差”的语境读音已由用户对确切 v4 音频听审通过；v5 多音字与 v6 通用断句规则均经 Content OS Voice Worker 重执行得到相同音频字节，因此复用该确切音频的 QA 与人审。人审证据为 `user-voice-approval-2026-11-07-v4-copula`；v6 真实执行与规则覆盖见 `content-os-data/evaluation-evidence/voice-syntax-generalization-v6-20261107/manifest.json`。任何再次改变音频字节的配方变化仍须重新人审。

### 完整断句体系

断句不是一组固定毫秒，也不是把每个标点都切开。完整体系由四个正交层组成：

1. **读音层**：多音字、专名和异读通过 Provider 私有拼音控制修正；不改变可见文案。
2. **结合关系层**：决定哪里必须连读、哪里可以停。词组内部、动词与补语、系词与短补语默认结合；转折、递进、对照和引出让语意决定前句是否收住。
3. **层级层**：停顿时长意图从短到长为“词组内无断点 → 列举微停 → 逗号/从句 → 冒号/分号过渡 → 句末 → 段落留拍 → 观点思考停顿 → 片尾落点”。这是相对顺序，不是通用毫秒表。
4. **实现层**：依次可用 Provider 标点调整、独立短语生成、段间接缝实测静音压缩、拼音注音；禁止用全局 speed 或未测静音冒充句法判断。最终 QA 同时保留原文、Provider 文本、分段映射、PCM 静音和人工听感。

当前产品覆盖：

| 能力 | 状态 |
|---|---|
| 词组内/无标点边界不切断、转折词前向绑定 | 通用分类已实现 |
| 逗号与句末分类、句末优先于逗号 | 通用分类已实现，时序以观察和人审为准 |
| 段落接缝留拍与有界实测静音压缩 | 通用执行已实现 |
| “主语，是短名词补语。”绑定并在句末断开 | 通用规则已实现，当前覆盖最多 12 字短补语 |
| “不是 A，是 B”对照句：A 收住、B 另起 | 通用句法规则 `contrastive_correction` 已实现，含非对照与“是不是”反例 |
| 动词结果补语完成后结束前句 | 通用规则 `resultative_predicate_completion` 已实现；当前覆盖常见动词补语组合，继续关系不触发 |
| “照明差”四声 | 已按质量/条件语境通用判定，并用差异、差遣、参差等反例测试；不再依赖单句词条 |
| 语义重音/焦点 | `zh-focus-emphasis-v1` 通用识别与本地段级执行已进普通 Worker；首条确切音频已通过用户听审，结论只绑定该 Audio，未固化“最后/三步”单句 |
| 关键观点与片尾落点 | 配方与复核规则已定义，不自动写入统一毫秒值 |

因此当前是“通用执行能力 + 通用系词规则 + 通用对照修正规则 + 通用结果补语规则 + 通用质量/条件多音字规则”。显式词条只保留无法可靠语境判断的专名、异读或经审例外，不再承担上述常规断句；有限规则集也不能被说成所有中文句法均已自动理解。

## 执行边界

调用前核对人物同意、实际 provider/model/runtime、完整文案覆盖、参考窗口和预算。模型许可与商业标记写入用量和用途限制，不因档案缺失或非商业标记增加普通产品门禁。失败、状态不明或已消费的调用不能用新幂等键偷偷重试。
